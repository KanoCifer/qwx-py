# Caching and TTL

Reference: the cache interface contract, cache key templates, and TTL details.

## Cache Interface

Without a `cache`, every request goes to upstream. The cache interface has only two methods; implement it yourself:

```python
from datetime import timedelta
from typing import Protocol


class Cache(Protocol):
    def get(self, key: str) -> bytes | None: ...
    def set(self, key: str, data: bytes, ttl: timedelta) -> None: ...
```

- A hit returns `bytes`, a miss returns `None`.
- Read and write failures raise. The SDK swallows cache errors and degrades to a direct upstream call, so implementations are free to raise.
- `ttl` is a relative duration.

The built-in `qwx.MemoryCache` is in-process and locked, and is **not recommended for production**. It has no background cleanup; expired entries are only removed when a `get` happens to hit them, so expired entries that are never accessed again stay in the dictionary forever and memory usage of a long-running process only grows. It suits test doubles and single-instance temporary caches only; in production use a shared cache such as Redis, and a multi-instance deployment needs a shared cache as well, otherwise the hit rate is diluted.

```python
import qwx

client = qwx.Client(auth, "abcxyz.qweatherapi.com", cache=qwx.MemoryCache())
```

## Redis Implementation

The Redis adapter is an optional dependency, install the extra:

```bash
pip install "qwx[redis]"
```

```python
import qwx
from qwx.redis_cache import RedisCache

# Build from a URL
cache = RedisCache.from_url("redis://127.0.0.1:6379/0")

# Or reuse an existing redis-py client; the pool, timeout and TLS are yours to configure
import redis

cache = RedisCache(redis.Redis(host="127.0.0.1", port=6379, db=0))

client = qwx.Client(auth, "abcxyz.qweatherapi.com", cache=cache)
```

Key points:

- Construction **does not connect to Redis**; the connection is established on the first read or write. A wrong address only surfaces on the first read or write.
- `from_url` requires redis-py to be installed and raises `ImportError` when it is not; `RedisCache(client)` accepts any object with `get` / `set` methods.
- The `ttl` of `set` is a relative duration, converted to Redis' `ex=` (integer seconds, rounded up, less than 1 second counts as 1 second). A non-positive ttl raises `qwx.InvalidParameterError` and nothing is written, since weather data without an expiry would stay stale forever.
- Cached values are stored as **raw JSON bytes**, and keys and values interoperate with the Go version when sharing one Redis: entries written by Python are readable by the Go version and vice versa.
- Do not enable `decode_responses=True` on the client. Values are stored and read as bytes, and enabling it breaks interop with the Go version.
- Cache errors are still swallowed by the SDK and degrade to a direct upstream call, so a Redis outage does not affect endpoint availability.

## Cache Keys

Keys are generated by the SDK and carry a generation prefix; the two generations do not share keys, so old cache entries are never read by the new parser.

| Module | Method | Key |
| --- | --- | --- |
| `qwx.v1.weather` | `current` | `qwx:v1:current:<lat>,<lon>` + suffix |
| `qwx.v1.weather` | `hourly` | `qwx:v1:hourly:<lat>,<lon>:h<hours>` + suffix |
| `qwx.v1.weather` | `daily` | `qwx:v1:daily:<lat>,<lon>:d<days>` + suffix |
| `qwx.v1.airquality` | `current` | `qwx:aq:v1:current:<lat>,<lon>` + suffix |
| `qwx.v1.airquality` | `daily` | `qwx:aq:v1:daily:<lat>,<lon>` + suffix |
| `qwx.v1.airquality` | `hourly` | `qwx:aq:v1:hourly:<lat>,<lon>` + suffix |
| `qwx.v1.airquality` | `station` | `qwx:aq:v1:station:<station_id>` + suffix |
| `qwx.v1.alert` | `current` | `qwx:alert:v1:<lat>,<lon>` + suffix |
| `qwx.v1.solarradiation` | `forecast` | `qwx:solarradiation:v1:forecast:<lat>,<lon>:h<hours>` + suffix |
| `qwx.geo` | `lookup_city` | `qwx:geo:city:<location>` + suffix |
| `qwx.geo` | `lookup_poi` | `qwx:geo:poi:<typ>:<location>` + suffix |
| `qwx.geo` | `poi_range` | `qwx:geo:poirange:<typ>:<location>` + suffix (includes radius `:r=<radius>`) |
| `qwx.geo` | `top_cities` | `qwx:geo:topcity` + suffix |
| `qwx.console` | `finance` | `qwx:console:finance` |
| `qwx.console` | `stats` | `qwx:console:stats` + suffix |
| `qwx.v7.ocean` | `tide` | `qwx:tide:<station_id>:<date>` |
| `qwx.v7.indices` | `indices` | `qwx:indices:<location>:t<type>:d<days>` + suffix |
| `qwx.v7.indices` | `indices_multi` | `qwx:indices:<location>:t<types>:d<days>` + suffix |
| `qwx.v7.minutely` | `minutely` | `qwx:minutely:<location>` + suffix |
| `qwx.v7.storm` | `list` | `qwx:storm:list:<basin>:<year>` |
| `qwx.v7.storm` | `forecast` | `qwx:storm:forecast:<storm_id>` |
| `qwx.v7.storm` | `track` | `qwx:storm:track:<storm_id>` |
| `qwx.v7.astronomy` | `sun` | `qwx:astronomy:sun:<location>:<date>` |
| `qwx.v7.astronomy` | `moon` | `qwx:astronomy:moon:<location>:<date>` + suffix |
| `qwx.v7.astronomy` | `solar_elevation_angle` | `qwx:astronomy:angle:<location>:<date>:<time>:<tz>:<alt>` |
| `qwx.v7.historical` | `weather` | `qwx:historical:weather:<id>:<date>` + suffix |

Key literals are frozen in released versions; changing them invalidates every cache entry already written. The key prefix of `qwx.v7.ocean` is `qwx:tide:` and not `qwx:ocean:`; the mismatch with the module name is deliberate, do not "fix it on the side".

Suffixes carry the query parameters that affect the result: language `:lang=<lang>`, new-generation local time `:localTime=1`, count `:n=<number>`, radius `:r=<radius>`, administrative division `:adm=<adm>`, search range `:range=<range>`, restricted city `:city=<city>`, time interval `:interval=<n>`, tilt angle `:tilt=<n>`, azimuth `:azimuth=<n>`, extra info `:extra=<extra>`, project `:project=<project>`, credential `:credential=<credential>`. Coordinates are always two decimal places, and `-0` is normalized to `0.00`.

The language segment holds the API code (`:lang=zh`), not the language name. It is the `api` field of `qwx.Lang`.

Suffix order is fixed: language → local time → count → radius → administrative division → search range → city → time interval → tilt angle → azimuth → extra info → project → credential. New parameters are always appended at the end; existing callers do not set them, so the key bytes stay exactly as they were at release.

Keys do not contain the API Host. Different hosts belong to different developer accounts, so do not share one Cache instance across accounts, otherwise results get mixed.

### How Keys Are Built

There is exactly one place that builds keys: `src/qwx/_cachekey.py`. Endpoint modules do not concatenate strings themselves; they declare two things, which family they belong to and which parameters affect the result.

| Family constant | Prefix root | Module |
| --- | --- | --- |
| `Family.WEATHER` | `qwx:v1:` | `qwx.v1.weather` |
| `Family.AIR_QUALITY` | `qwx:aq:v1:` | `qwx.v1.airquality` |
| `Family.ALERT` | `qwx:alert:v1:` | `qwx.v1.alert` |
| `Family.GEO` | `qwx:geo:` | `qwx.geo` |
| `Family.TIDE` | `qwx:tide:` | `qwx.v7.ocean` |
| `Family.INDICES` | `qwx:indices:` | `qwx.v7.indices` |
| `Family.MINUTELY` | `qwx:minutely:` | `qwx.v7.minutely` |
| `Family.SOLAR_RADIATION` | `qwx:solarradiation:v1:` | `qwx.v1.solarradiation` |
| `Family.STORM` | `qwx:storm:` | `qwx.v7.storm` |
| `Family.ASTRONOMY` | `qwx:astronomy:` | `qwx.v7.astronomy` |
| `Family.HISTORICAL` | `qwx:historical:` | `qwx.v7.historical` |
| `Family.CONSOLE` | `qwx:console:` | `qwx.console` |

The shape is fixed: family prefix + location segment + parameter segment.

- The location segment is concatenated in append order: endpoint name, coordinates, station ID, place ID, count segment (`:h24`).
- The coordinate segment is formatted by `_cachekey`: two decimal places, `-0` normalized to `0.00`. The new generation puts latitude first (`path_coord`); the old generation and GeoAPI use `Location.query()` for the location segment, longitude first.
- The parameter segment is always last, in the order language → local time → count → radius → administrative division → search range → city → time interval → tilt angle → azimuth → extra info → project → credential.

Query parameters that affect the result are declared with the same `qwx._cachekey.Params`, which generates both the upstream query string and the key suffix. Adding a parameter means changing this one place only, so a parameter cannot silently miss the key.

```python
# src/qwx/v1/weather/client.py
def _params(opts: Options) -> Params:
    return Params(lang=opts.lang.api, local_time=opts.local_time)
```

`None` represents "the endpoint has no radius parameter". A radius of 0 enters the key only and is not sent upstream, where upstream applies its own default.

Tilt angle and azimuth also use `None` to mean "do not send"; 0 is a valid value and when not `None` it is sent upstream along with the 0.

## TTL

| Endpoint | Endpoint constant | Default TTL | Basis |
| --- | --- | --- | --- |
| Current weather | `qwx.v1.weather.EndpointCurrent` | 10 minutes | Upstream update cadence |
| Hourly / daily forecast | `qwx.v1.weather.EndpointHourly` / `EndpointDaily` | 1 hour | Same as above |
| Current air quality | `qwx.v1.airquality.EndpointCurrent` | 30 minutes | Upstream updates hourly |
| Air quality forecast | `qwx.v1.airquality.EndpointDaily` / `EndpointHourly` | 1 hour | Same as above |
| Monitoring station | `qwx.v1.airquality.EndpointStation` | 30 minutes | Same as above |
| Weather alerts | `qwx.v1.alert.Endpoint` | 5 minutes | Upstream updates every 5 minutes |
| Minutely precipitation | `qwx.v7.minutely.Endpoint` | 5 minutes | Upstream updates every 5 minutes |
| Tide / life indices | `qwx.v7.ocean.Endpoint` / `qwx.v7.indices.Endpoint` | 1 hour | Data update cadence |
| Solar radiation forecast | `qwx.v1.solarradiation.Endpoint` | 1 hour | Upstream updates the forecast every 15 minutes |
| Tropical cyclone list | `qwx.v7.storm.EndpointList` | 24 hours | The list barely changes within a day |
| Cyclone forecast / track | `qwx.v7.storm.EndpointForecast` / `EndpointTrack` | 1 hour | Upstream updates every few hours |
| Astronomy | `qwx.v7.astronomy.EndpointSun` and the other two | 24 hours | Data is fixed per date and does not change within a day |
| Historical weather | `qwx.v7.historical.Endpoint` | 24 hours | Data is fixed per date and does not change once the past |
| GeoAPI | `qwx.geo.EndpointCity` and the other three | 24 hours | Geographic information rarely changes |
| Console | `qwx.console.EndpointFinance` / `EndpointStats` | 1 hour | Upstream data is current only up to the previous hour or earlier |

### Custom TTL

The default duration is decided by the endpoint module; pass a `ttl_policy` to adjust it:

```python
from datetime import timedelta

import qwx
from qwx.v1.airquality import EndpointCurrent as AQCurrent
from qwx.v1.weather import EndpointCurrent

client = qwx.Client(
    auth,
    "abcxyz.qweatherapi.com",
    cache=cache,
    ttl_policy=qwx.TTLMap(
        {
            EndpointCurrent: timedelta(minutes=5),
            AQCurrent: timedelta(0),  # do not cache this endpoint
        }
    ),
)
```

`qwx.TTLMap` is the most common shape: keys are endpoint constants, values are cache durations. When a key is missing the endpoint's default duration applies; a value of 0 means the endpoint is not cached.

Use `qwx.TTLPolicyFunc` when you need to adjust by time or load:

```python
policy = qwx.TTLPolicyFunc(
    lambda endpoint, default: timedelta(seconds=10) if endpoint == EndpointCurrent else default
)
```

`default` is the built-in default duration of the endpoint module; return it unchanged when the policy has no opinion. The policy is evaluated on every request, so implementations must be concurrency-safe.

To bypass the cache for a single request, use a context override; no endpoint signature changes:

```python
with client.override_ttl(timedelta(0)):  # neither read nor write the cache
    weather.current(loc)
```

The override takes priority over the policy and the endpoint default. The override uses `contextvars`, so it works for both sync and async, and async tasks do not interfere with each other.

Duration resolution order: single-request context override > `TTLPolicy` > built-in default duration of the endpoint module.

Requests with an empty endpoint (external code constructing a `qwx.Request` without filling in `endpoint`) do not take part in policy matching, the policy is not called, and the cache duration is determined solely by `Request.ttl`.

### TTL and Cache Keys

Changing the TTL does not change cache keys. Already written entries expire according to the TTL at write time, so lowering the policy does not make them expire early. To take effect immediately, replace the cache instance or delete the keys manually.
